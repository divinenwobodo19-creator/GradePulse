## 2. Ground Rules for Every Session

1. **Read before you write.** Start each session with this handbook + `SAM_TECHNICAL_HANDOFF.md`. Check for changes since your last session before acting.
2. **Log decisions, not just code.** Architectural choices, API/schema changes, or cross-role-affecting bugs go in the Decision Log before the session ends.
3. **The API contract belongs to Sam.** Infrastructure, Data, QA, and Docs treat the 16 documented endpoints and JWT auth as fixed unless Sam's session explicitly changes them.
4. **Don't silently change contracts.** Flag breaking changes explicitly in the log — don't just merge them.
5. **No session has roadmap authority.** Divine decides scope and priority; agents execute and advise.

---

## 3. Critical Facts From Sam's Handoff (v0.1)

- **Single-worker constraint — top production risk.** Brain state is in-memory; multiple uvicorn workers fork and silently diverge. Infrastructure must resolve this before any pilot traffic. Run with `--workers 1` until then.
- **JSON storage is a known, planned ceiling** — fine under ~50 students. SQLite migration is already scheduled for v0.2 (P2). Don't re-litigate this decision; execute it when its turn comes.
- **95 tests already exist and pass** — covering adaptive gamma, anti-gaming reward shaping, full API, brain core, hybrid model, multi-school/tenant logic, LinUCB arm selection, Neural Score, sync/locking, and backup. QA extends this baseline; it doesn't duplicate it.
- **Multi-tenant hierarchy is fixed:** `School → SchoolClass → Student`. Any new feature must respect this, not flatten it.
- **v0.2 roadmap is already prioritized:**
  | Feature | Priority |
  |---|---|
  | Thompson Sampling cold-start | P0 |
  | `/group_recommendations` endpoint | P1 |
  | Context diversity regularization | P1 |
  | SQLite migration | P2 |
  | Off-policy evaluation (OPE) | P2 |
- **17-dim context vector** (8 shared student features + 9 arm-specific content features) is the model's input contract — Data Engineer's ingestion pipeline must map real pilot data into this shape exactly.
- **Neural Score** is the standing health check (7 weighted dimensions, 0-10 each) — QA and Docs should treat a dropping Neural Score as a signal worth investigating, not just a number to report.
