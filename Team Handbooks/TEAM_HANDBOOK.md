## 2. Ground Rules for Every Session

1. **Read before you write.** Start each session with this handbook + `PROJECT_INDEX.md` + `SAM_TECHNICAL_HANDOFF.md`. Check for changes since your last session before acting.
2. **Log decisions, not just code.** Architectural choices, API/schema changes, or cross-cutting bugs go in the Decision Log before the session ends.
3. **The API contract belongs to the Backend Engineer.** The documented endpoints and JWT auth are fixed unless this session explicitly changes them — flag breaking changes loudly in the log, don't just merge them.
4. **Don't silently change contracts.** Flag breaking changes explicitly in the log — don't just merge them.
5. **No session has roadmap authority.** Divine decides scope and priority; the Backend Engineer executes and advises.

## 3. Critical Facts From Sam's Handoff (v0.1)

- **Single-worker constraint — RESOLVED.** `sync.py` with BrainSynchronizer provides file-based locking. Multiple uvicorn workers are safe. See `linucb_brain/sync.py`.
- **JSON storage is a known, planned ceiling** — fine under ~50 students. SQLite migration is already scheduled for v0.2 (P2). Don't re-litigate this decision; execute it when its turn comes.
- **484+ tests exist** — covering adaptive gamma, anti-gaming reward shaping, full API, brain core, hybrid model, multi-school/tenant logic, LinUCB arm selection, Neural Score, sync/locking, backup, pilot-grade data, and ingest validation. QA extends this baseline; it doesn't duplicate it.
- **Multi-tenant hierarchy is fixed:** `School → SchoolClass → Student`. Any new feature must respect this, not flatten it.
- **v0.2 roadmap is already prioritized:**
  | Feature | Priority |
  |---|---|
  | Thompson Sampling cold-start | P0 |
  | `/group_recommendations` endpoint | P1 |
  | Context diversity regularization | P1 |
  | SQLite migration | P2 |
  | Off-policy evaluation (OPE) | P2 |
- **17-dim context vector** (8 shared student features + 9 arm-specific content features) is the model's input contract — Data Engineer's ingestion pipeline must map real pilot data into this shape exactly.
- **Neural Score** is the standing health check (7 weighted dimensions, 0-10 each) — QA and Docs should treat a dropping Neural Score as a signal worth investigating, not just a number to report.

- **Which port should the real backend own for dev? — RESOLVED 2026-09-27 (Mia + Backend Engineer).** **`:8000` is the canonical backend port** — it is what `docker-compose.yml` (`${PORT:-8000}:8000`), the Dockerfile healthcheck, and `DEPLOYMENT.md` all assume, so the real engine now runs there. The demo mock moved from `:8000` to **`:8020`** (`MOCK_PORT`-overridable) so it can never take the backend's port again. No `.env.local` is needed: the frontend default is `http://localhost:8000`. Verified end-to-end — `http://localhost:3000/api/health` → `engine: "GradePulse"`.
  - **Note for everyone:** the frontend no longer reads `NEXT_PUBLIC_API_URL` in the normal path. The browser calls same-origin `/api`, and Next rewrites it server-side to `API_URL` (default `http://localhost:8000`). Setting `NEXT_PUBLIC_API_URL` still works as a direct-to-backend escape hatch, but it bypasses the proxy and brings back the CORS dependency — don't use it for dev.
  - `next.config.ts` prints a loud warning at dev start if `API_URL` resolves to a non-`GradePulse` engine, mirroring the Backend Engineer's `engine` check in `tests/live_api.py`. The mock cannot silently become the rewrite target.
- **Auth storage decision (frontend, needs backend + Divine):** the JWT is in `localStorage`, so any XSS can exfiltrate it and the 7-day token can't be revoked client-side. Moving to an `HttpOnly; Secure; SameSite=Strict` cookie is the real fix, but it needs backend cooperation and changes how the frontend calls the API (credentials instead of an `Authorization` header). **Blocks nothing today; should be decided before the pilot.**
